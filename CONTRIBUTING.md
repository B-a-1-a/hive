# Contributing to Hive

Hive is currently in an owner-led shaping phase. The previous contributor backlog is superseded. Wait for a new task or direct agreement with Bala before starting feature work.

When contributor work resumes, use the GitHub issue as the shared assignment record. Agree on an owner and intended outcome, check for overlapping work, and keep implementation and verification within that scope. Personal agent memory does not assign a task. Split work only where contributors can make progress independently.

Read the affected code and nearby tests before editing. Use the [development loop](.agents/skills/development-loop/SKILL.md) as a flexible guide: understand the intended behavior, make a focused change, test what can break, and explain the evidence. Use independent verification for substantial changes. Small changes need proportionate checks.

Keep provider credentials, browser profiles, and private work out of commits. Test against separate Hive data. Preserve upstream licensing and external-service compatibility. Main retains its required checks and review protection.

The inherited technical guidance is in [AGENTS.md](AGENTS.md) and [the development guide](docs/operations/development.md). CONTRIBUTING.upstream.md is retained as historical upstream guidance, not Hive's assignment policy.
